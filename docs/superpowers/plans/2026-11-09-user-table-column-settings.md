# 用户级表格列设置实施计划

> 实施时按任务顺序使用 Superpowers 的 executing-plans 流程。统一接入所有现有业务列表，并为后续新增列表提供同一接入方式。

**目标**　按参考图改造列设置，支持勾选显示、拖动排序、固定列和调整列宽，并通过现有用户配置接口保存和恢复。

**方案**　复用 Vue、Naive UI、`VueDraggable` 和系统请求客户端。把列配置读写、列投影和拖宽保存放进公共表格层，普通列表与分页列表共用。每张业务列表使用稳定的页面标志作为配置编码，按登录账号读取。

## 交互设计

- 点击表格右上的设置图标，打开「列设置」弹窗。左侧用复选框网格展示可设置的列，支持全选、半选。右侧展示已勾选的列，通过拖动手柄排序并设置固定方式。窄屏改成上下布局。
- 可固定列支持靠左、靠右和取消固定。按图中提示，用户最多固定 7 列，已选但未固定的列不计入上限。固定列放在各自侧边，组内保持排序。菜单管理的「菜单名称」始终可见，操作列继续由页面固定在右侧，两者的必显规则由页面定义，系统固定的操作列不计入上限。
- 点击「应用」保存显示状态、顺序和固定方式，成功后更新表格并关闭弹窗。点击「关闭」、右上角关闭或按 Esc 时丢弃草稿。「恢复默认」先恢复草稿，点击「应用」后同时恢复默认列宽。
- 列宽只通过拖动列表表头右边缘调整。拖动期间实时预览，松手后立即提交一次最终宽度，无需打开弹窗或点击「应用」。每次有效拖动各保存一次，拖动过程和宽度未变的手势均不发送保存请求。按列定义约束最小宽度，上限建议为 1200px。
- 各列表继续沿用自身的默认字段和顺序。图中的字段名称用于参考布局和操作方式。

## 任务 1　接入现有用户配置接口

现有 `UserConfigController` 和 `UserConfigServiceImpl` 按登录用户的 `userId + type + code` 定位记录。前端通过现有 `request` 客户端发请求，业务前缀及认证由客户端统一处理。

| 操作     | 请求                                                                                    | 返回                                          |
| -------- | --------------------------------------------------------------------------------------- | --------------------------------------------- |
| 查询     | `POST /user-config/detail`，请求体 `{ "type": "CUSTOM_COLUMN", "code": "manage-menu" }` | `UserConfigDetailVO\|null`，无记录时为 `null` |
| 保存     | `POST /user-config/add-or-update`，请求体在查询参数上增加字符串 `content`               | 保存后的 `UserConfigDetailVO`                 |
| 恢复默认 | 复用保存接口，将默认列配置写入 `content`                                                | 与「应用」使用相同的成功、失败处理            |

- [ ] 新增 `src/service/api/user-config.ts` 及对应 API 类型，在 API 入口导出。请求体无需传 `userId`。查询和保存直接使用稳定的页面标志，当前为 `manage-menu`、`manage-user`、`manage-role`。同一页面有多张独立业务列表时，用「页面标志-列表用途」区分，例如 `manage-user-history`。
- [ ] 在联调环境确认 `sys_user_config` 的字段容量和 `(user_id, type, code)` 唯一约束。现有服务先查后写，需要验证两个页签同时首次保存时只产生一条记录。若当前环境无法保证，补齐唯一约束并使写入可并发重试或原子更新。现有接口契约可继续使用。
- [ ] 用两个账号分别保存同一配置编码，再各自查询，确认返回各自配置。另用同一账号的不同编码验证表格间隔离。

## 任务 2　配置格式与读写规则

`content` 是 JSON 字符串。下例只展示两列的编码结构；实际保存包含可配置的列，数组顺序即用户顺序。

```json
{
  "version": 1,
  "columns": [
    { "key": "menuName", "visible": true, "fixed": "left", "width": 180 },
    { "key": "menuType", "visible": true, "fixed": null, "width": 100 }
  ]
}
```

- [ ] 新增可复用的列配置 composable 和配置合并逻辑。使用稳定列键匹配页面默认定义，保存显示状态、顺序、固定方式和像素宽度。标题、渲染函数、按钮权限、树节点及固定操作列继续取页面定义。
- [ ] 进入页面时并行请求数据和配置。收到配置后再展示已设置的列，避免默认列闪一下。查询返回 `null` 时使用默认列。配置查询失败时用默认列继续浏览，提供重试入口，恢复查询前暂停写入，避免覆盖原设置。
- [ ] 兼容历史配置和字段演进。移除未知列键和重复键，新增列按默认顺序补到用户设置之后，必显列从页面定义恢复，宽度按有效数字和列范围校验。无法解析的内容以默认值显示，覆盖需用户明确确认。遇到更高版本配置时保留服务器原值。
- [ ] 按账号会话和表格编码隔离异步结果。切换账号时清空当前配置，忽略旧请求结果及尚未发送的写入。同一表的「应用」与拖宽保存共用串行队列。松手立即入队，空闲时立即发请求，有写入在途时等其完成再依次发送。每次提交基于最新已确认配置合并本次变更，避免旧快照覆盖其他列或把失败的改动带入后续保存。
- [ ] 保存失败时，弹窗保留草稿并允许重试。拖宽保存失败时提示用户，且在没有该列更新的待保存宽度时恢复上次已确认值。

## 任务 3　重做列设置弹窗

- [ ] 在 `src/components/advanced/table-column-setting.vue` 实现左右两栏和弹窗页脚。复用 `NModal`、`NCheckbox` 和 `VueDraggable`。右侧只提供排序和固定设置，拖动排序仅响应手柄。
- [ ] 列设置与已应用的 `columnChecks` 解耦，打开时复制当前设置，提交成功后一次性替换。补充全选、必显列、固定 7 列上限、保存加载态及按钮文案。
- [ ] 由 `src/components/advanced/table-header-operation.vue` 统一接入弹窗。列设置读写由公共表格层提供，各业务页面只传配置编码和默认列定义。
- [ ] 验证取消、恢复默认、全选和半选、拖动排序、固定上限，以及保存失败后重试。切换界面语言时列标题切换，已保存的顺序和宽度按列键继续应用。

## 任务 4　所有业务列表接入与列宽调整

- [ ] 在 `src/hooks/common/table.ts` 为 `useNaiveTable` 和 `useNaivePaginatedTable` 提供同一套用户列配置和拖宽事件适配。按可见列的有效宽度重算横向滚动区域。当前三个业务列表在同一版本接入。
  - 菜单管理 `src/views/manage/menu/index.vue` 使用 `manage-menu`，保留树形展开、按钮悬浮表格和行操作。
  - 用户管理 `src/views/manage/user/index.vue` 使用 `manage-user`，保留筛选、分页、行选择和操作。
  - 角色管理 `src/views/manage/role/index.vue` 使用 `manage-role`，保留筛选、分页、行选择和操作。
- [ ] 通过当前 Naive UI 的 `resizable` 和 `onUnstableColumnResize` 获取拖动的列键和限制后的宽度。拖动过程中只预览，在鼠标松开时立即提交最终宽度。把监听与持久化集中在表格适配层，升级 Naive UI 时复验。
- [ ] 核对 Naive UI 的内部拖宽状态是否覆盖服务器宽度。当前版本的清空方法属于内部注入，应用或恢复默认后若仍使用旧宽度，通过表格实例的渲染键清除缓存，并用受控状态恢复当前分页和树展开。
- [ ] 把「提供稳定页面标志并复用公共表格列设置」写入新增业务列表的接入约定。检查现有三个页面均经公共入口接入。按钮详情等说明性小表格沿用其独立展示方式。
- [ ] 联调验证三个列表的桌面拖宽、每次松手的保存请求、应用后重进和刷新。检查固定列、横向滚动、移动端弹窗，以及窄屏下操作列和按钮浮层可用。

## 验收

1. 菜单、用户、角色管理首次进入时各自使用默认列。隐藏、排序、固定并应用，刷新后分别恢复各自配置。
2. 连续完成两次有效的表头拖动，每次松手后提交一次最终宽度，刷新后恢复最后保存的值。恢复默认并应用后，刷新仍为默认值。
3. 点击关闭或 Esc 不写入。查询失败、保存失败和旧配置格式均有明确行为。
4. 两个账号的设置独立。同账号多个表格按编码隔离，同一配置并发首次保存后只存在一条记录。
5. 运行 `pnpm typecheck`、现有测试和生产构建，并在 Chrome 完成上述交互检查。
