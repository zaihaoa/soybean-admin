# 双栏导航与菜单分类实施计划

> 实施时按任务顺序使用 Superpowers 的 executing-plans 流程。本文覆盖前端 soybean-admin 和后端 wd-cloud3。

**目标**　桌面侧栏收缩时按需打开二级面板，使用图 2 的双栏布局。菜单管理支持配置「所属分类」，二级面板和展开时的菜单树共用分组规则。

**架构**　所属分类直接保存为 `sys_menu.menu_group_name` 中的可空文本。菜单新增、编辑和读取沿用现有接口。前端按父菜单和分类名称对已授权菜单分组。原有菜单 ID、路由名和角色授权关系继续作为导航与授权依据。

## 交互范围

| 场景                                                 | 预期                                                                                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 桌面首次进入首页                                     | 侧栏默认收缩，只显示 72px 一级栏。                                                                                          |
| 收缩时点击有可见子菜单的一级目录                     | 在一级栏右侧打开 180px 二级浮层，页眉、页签和正文维持原位。浮层外的页面显示半透明遮罩，面板标题显示当前目录，例如「系统」。 |
| 点击遮罩、再次点击同一一级目录，或选中子菜单         | 二级面板收起。再次打开时，高亮当前子菜单。                                                                                  |
| 点击首页等无子菜单项                                 | 跳转对应页面并收起二级面板。                                                                                                |
| 直接访问、刷新子页面，或通过页签和浏览器历史切换页面 | 二级面板保持收起，一级栏按当前路由高亮所属目录。隐藏的详情页沿用现有 `meta.activeMenu` 高亮规则。                           |
| 点击底部按钮展开                                     | 恢复 192px 单栏树形菜单，显示相同分组并展开当前菜单路径。再次收缩时只显示一级栏。开关沿用现有图标和无悬浮提示的交互。       |
| 手机端                                               | 沿用现有页眉按钮和遮罩抽屉，在抽屉内显示单栏分组树。                                                                        |

以上尺寸沿用目前的默认宽度及现有 180px 二级栏配置。分类标题用低强调文字，作为分组标签显示。

「所属分类」是一级目录下直接子菜单的可选单行文本。去掉首尾空白后，同一父菜单下完全相同的名称合并为一组，不同父菜单下的同名分类各自显示。按现有菜单顺序遍历，分组以首个可见成员的出现顺序排列，组内沿用菜单顺序。未分类项放在分组后直接显示，彼此保持原顺序。全部未分类时，继续显示原来的列表形式。

例如，「系统」下的「用户管理」「角色管理」都填写「基础」，「菜单管理」填写「配置」，则显示「基础」和「配置」两组。修改一项的分类名只移动这一项，要给整组改名时需要更新同组的各个菜单。

## 任务 1　数据库结构与现有数据

- [ ] 迁移前检查目标数据库 `SHOW CREATE TABLE sys_menu`，确认字符集和现有迁移约定。新环境使用后端 `doc/db/init.sql` 中的菜单表定义。
- [ ] 在后端 `doc/db/` 添加带版本的增量 SQL，为 `sys_menu` 增加 `menu_group_name VARCHAR(100) NULL DEFAULT NULL`。已有菜单自然为 `NULL`。分组按当前已授权菜单在前端计算，因此本次数据库变更仅涉及这一列。
- [ ] 在已有菜单的测试库验证增量。核对历史菜单分类为 `NULL`，菜单数量、路由字段和角色菜单关系与迁移前一致。可在测试环境通过编辑菜单填写「基础」和「配置」验证效果。

## 任务 2　后端菜单写入

**主要位置**　`wd-system/wd-system-server/src/main/java/com/wd/system/basic/` 下的 `Menu.java`、`MenuAddDTO.java`、`MenuUpdateDTO.java` 和 `MenuServiceImpl.java`。

| 方法及接口         | 契约                                                                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /menu/add`   | 接收可选文本 `menuGroupName`，如 `"基础"`。省略、传 `null` 或只填空白时保存为 `NULL`。                                                                        |
| `PUT /menu/update` | 同一父目录下，省略字段保留原分类，传 `null`、空字符串或空白清空分类。换父目录且省略字段时清空原分类；显式传文本且新父目录符合条件时，以新父目录下的分类处理。 |

- [ ] 新增和更新沿用现有 `MENU_ADD` 和 `MENU_UPDATE` 权限。服务端统一去首尾空白、将空值归一为 `null`，并校验非空名称为最多 100 字符的单行文本。一级目录的直接子项可以填写；其他层级提交非空文本时返回校验错误。
- [ ] 一级目录下有已分类子项时，先清空这些子项的分类，再移动、删除目录或将它改为普通菜单。分类写入和目录资格变化使用事务内行锁协调。
- [ ] 更新 DTO 区分字段省略与显式 `null`，确认清空能落库。现有 `alwaysUpdateSomeColumnById` 的空值策略需要实测。若当前字段更新策略跳过空值，在现有事务内显式写空。操作日志记录实际的分类变更。
- [ ] 菜单写入继续沿用 `clearMenuCacheAfterCommit`。删除最后一个组员、清空其分类或将其移出该组后，该组在下一次读取和渲染时自然消失。

## 任务 3　分类数据进入菜单读取链路

- [ ] 为 `MenuDetailVO`、`MenuTreeVO` 增加可空字符串 `menuGroupName`，通过 `MenuConverter` 从同名实体字段映射。权限菜单继续按现有规则筛选，分类名随可访问的菜单返回。
- [ ] 核对四个读取入口。管理树 `GET /menu/menu-tree`、详情 `POST /menu/detail`、权限树 `GET /menu/user-permission-menu-tree`、登录后的 `GET /user/current-user-info` 中的 `authMenuList`。最后一个目前经 `UserServiceImpl` 调用权限树服务，复用 `MenuTreeVO` 即可。现有接口响应包裹结构继续使用。
- [ ] 验证角色仅能看到获授权的原菜单。修改分类名或清空后，重新请求详情、管理树与权限树时读取到新值。旧数据继续返回无分类。

## 任务 4　前端菜单管理与分类投影

- [ ] 在 `src/typings/api/system-manage.d.ts` 和 `src/typings/api/auth.d.ts` 增加 `menuGroupName?: string | null`，兼容旧响应缺省。现有新增、更新、详情和菜单树请求复用原接口。
- [ ] 在 `src/views/manage/menu/modules/menu-operate-modal.vue` 的上级菜单之后增加可清空的「所属分类」单行 `NInput`，占位提示为「例如：基础」。选择一级目录作为父节点时显示，从详情回填，切换父目录时清空并允许重新填写。提交前去首尾空白，清空时发送 `null`。
- [ ] 在 `src/store/modules/route/menu-permission.ts`、`shared.ts` 和对应类型中把分类名带入已授权的菜单项。目前 `VITE_AUTH_ROUTE_MODE=static`，从 `authMenuList` 按 `routeName` 合并。动态路由模式兼容字段缺省。
- [ ] 静态模式沿用已生成的路由父子关系。后台授权树的父目录与静态路由不一致时，该项在静态树中按未分类显示，直到两边的父目录一致。
- [ ] 写一个纯投影函数，接收同一父菜单下按现有顺序排列的可见子项，按分类名生成 Naive UI 的 `type: 'group'` 选项。分组键由带前缀的父菜单键和分类名生成，菜单项键仍使用原路由键。保留原菜单树供查找路径、搜索、面包屑和角色授权。
- [ ] 保存成功后沿用现有的管理树刷新。首版导航分类以刷新页面后重新读取当前用户信息为准，避免编辑分类时重置当前路由和已打开页签。
- [ ] 验证同一目录下的同名合并、首尾空格归一、跨目录同名隔离、未分类兼容、移出最后一项、显式清空和角色过滤。按现有中英文资源补齐字段、提示和校验文案。

## 任务 5　桌面双栏导航

- [ ] 继续使用默认 `vertical` 布局。以 `src/layouts/modules/global-menu/modules/vertical-mix-menu.vue` 为参考，复用二级面板、Naive UI 菜单和 `SimpleScrollbar` 的做法。为收缩分支使用可键盘操作的一级按钮，替换原来收缩态 `NMenu` 的悬浮下拉。展开分支仍在 `vertical-menu.vue` 渲染树形菜单。
- [ ] 通过布局上下文共享二级面板的打开状态。用户点击一级目录时可临时打开面板。路由变化时收起面板，一级栏继续按当前菜单树路径高亮。子项不可见或目录已消失时收起面板。
- [ ] 从 `useMenu().selectedKey` 和 `routeStore.getSelectedMenuKeyPath` 确定选中路径。将 180px 二级面板定位在 72px 一级栏右侧，覆盖在内容上方。分类菜单应用到二级面板和展开树。
- [ ] 手机端走原单栏抽屉分支。验证桌面到手机的断点切换、内容区全屏、短窗口滚动、长标题省略、亮暗主题及键盘 Tab、Enter 操作。
- [ ] 在 Chrome 验证首页首次进入、点击「系统」、鼠标移出、选中子项、点击首页、展开后重新收缩、直接访问子页面及回退操作。使用普通角色再验证只有一个有权限的分组时的效果。

## 上线顺序与验收

1. 在测试库执行增量 DDL 和兼容验证，先部署支持新增字段的后端，再部署前端，最后按需在菜单管理中填写「基础」等分类。
2. 前端运行 `pnpm typecheck`、`node --import tsx --test tests/*.test.ts` 和 `pnpm build`。给分组投影补充授权后空组、稳定排序和旧数据三类回归验证。
3. 后端运行 `mvn -pl wd-system/wd-system-server -am -DskipTests compile`。现有父 POM 默认跳过测试。若补充菜单分类测试，运行时显式加 `-Dmaven.test.skip=false`，并通过测试环境 API 验证文本校验、字段缺省、显式清空及权限隔离。
4. 若需要回滚，先回退前端和服务端应用，保留新增列和已填写的分类名。下次发布可以继续读取现有分类。
